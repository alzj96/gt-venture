# gt-venture · 创业诊断

面向中国创业者的项目诊断技能。在动手之前把项目问清楚，指出在中国做这件事要过哪几道闸，把结论存档以便下次接着聊。

**主要写给第一次做这件事的人**——学生、刚毕业、想做个副业、有个想法但不知道从哪儿开始验证的。它会区分"没有资源"和"没有优势"，不会把前者当成后者。

跑在 **WorkBuddy**、**豆包**、**Claude Code** 上，同一套 `SKILL.md`，不用改。

**名字的来历**：`gt` = ground truth，机器学习里那份用来对照的真值——**没有它，任何"准确率"都是自说自话**。这正是这个技能的铁律：没有证据，不给判断。`venture` 是它落的地方；同一个词根下还会有别的 `gt-*`。

安装见 [INSTALL.md](INSTALL.md)。**它站在什么立场上，见 [ETHOS.md](ETHOS.md)**——四条信念，每条都带"什么能推翻它"。诊断不是中立的，同一个项目换一套信念就是另一个结论，所以信念先摆出来，你不同意哪条就知道该打哪份报告的折扣。

## 它做什么

三种模式，按**你卖的是什么**分，不按规模分：

| | 副业体检 | 轻量筛查 | 全面诊断 |
| --- | --- | --- | --- |
| 适用 | **卖自己的时间和手艺**（接单、外包、周末摆摊） | 有个项目想法，先看有没有硬伤 | 有个项目想法，要结论 |
| 做什么 | 四问 | 三项一票否决检查 | 六问 + 失败模式 + 查知识库过四道闸 + 前提确认 + 对抗评审 + 报告 |
| 轮次 | 6-8 | 4-6 | 15+ |
| 产出 | 报告 | 报告 | 报告 |

**三种模式都出报告**，而且都会额外导出一份单文件 HTML（[看一份示例](assets/sample-report.html)）——样式内联、不连外网，可以直接发给合伙人看。报告正文照样发进对话，HTML 是附加的。

分不清就问一句：**你是想接活赚钱，还是想做一个东西卖给很多人？**

档案共用，可升级，答过的不重问。

### 副业体检为什么单独做

六问是给"做一个产品卖给一个市场"设计的，**对接单不适用**——需求真不真，收到钱就知道了。

接单的真问题是另外两个：

**一、在职做副业会不会出事。** 这一问必须早问，不能等到最后——踩了的话前面赚的全是负的。三样要查：劳动合同里的兼职条款、竞业限制（**它管的是离职之后**，而且用人单位要按月给经济补偿）、职务发明归属（**用了公司电脑、服务器、内部资料的，可能不归你**）。

**二、时薪能不能涨。** 接单的收入是线性的——做得越好越忙，忙到头就封顶。涨价的路只有三条：涨价、复用、交付出去。三条都选不了的，**那是一份加班费更高的第二工作，不是副业**——这话要说出来。

## 它和"找个 AI 聊聊创业想法"差在哪

我们跑过对照实验：同一份人物剧本，一边走这个技能，一边走一个没有技能的通用助手，还有一边走 gstack 的 `/office-hours`。结论写在 [docs/差分测试-第一轮结果.md](docs/差分测试-第一轮结果.md)。

**诚实的结论是：不在"知道得更多"。**

在知识库覆盖不到的领域，我们和对照组的中国知识同源——都来自模型和联网。差别在这几处：

**一、合规核查是制度不是运气。** 对照组做了合规核查，但那是模型自己想起来要做的（10 次检索里 9 次是自主判断）。我们的指令写死了要做，而且写死了怎么做。

**二、主体资格优先于类目资质。** 「我老婆是小学数学老师，她手上有 40 个家长」——用户认为的核心资产正是项目的违法点。只查类目会给出一个引用规范、来源清晰、却完全答偏的结论。那比说不知道更危险。

**三、对第一次创业的人有专门的校准。** 第 6 问「你凭什么」对没有资源的人是打击不是诊断——所以它有一个分支：能全职投入多久、这段时间结束时你希望手上有什么。**时间窗口是真资源，但只有在有明确产出目标时才是。** 另外 F15 专门管"把我自己想要当成全部的用户研究"这条第一次创业最容易踩的。

**四、规则带一手源原文、拉取日期和链接。** 模型能告诉你"可能需要办证"，给不了你逐字原文和它是哪天核对的。

**五、这一行的底子提前整理好，不在对话里现搜。** 在 WorkBuddy 上实跑时，两次联网查的都是「上门喂猫这一行有谁在做、收多少钱」——这种东西该提前整理好。现在的知识库把 20 个门类要不要许可、29 个常见小生意谁在做收多少钱，都在开发阶段逐字核过原文、整理成卡；诊断时先查库、只读命中的那一节，库里没有才联网，**搜到的当线索不当规则**，报告里记一行「知识库缺口」。

上面四轮差分都是**知识库扩建之前**测的；扩建之后还没重测。

### 还有一处差别，是第二轮抄回来的

**问题本身要能被推翻，不能只是开放题。**

一个还没想清楚的人，生成很难，纠正很容易。问他「你的用户是谁」，他给你一个标签；把「给三年级学生的家长」摆到他面前，他会立刻说「不是家长，是老师」——那一句纠正里的信息量，比三轮开放提问都大。

所以流程里有三处是**摆结论让你推翻**：

- **动手问之前**：用一句话说回你要做的事（给谁 / 做哪一件事 / 拿到什么），猜的部分标出来，问你「哪个词用错了」
- **写报告之前**：把整份结论踩的 3-5 条前提摆出来，每条标〔你说的〕〔我查的〕〔我推的〕，并点名哪一条最要命
- **报告里**：写清楚「我否掉了什么」——你手上有我不知道的信息时，你能精确地反驳哪一句

配套的两条是本土化的：**每句话标出处**，以及**问「哪里不对」而不是「对不对」**。国外的框架不写这两条，它们默认创始人会反驳；第一次创业的人不会，得把反驳的门槛降到只要指出一个词。**「对对对」不算确认。**

细节和取舍见 [docs/提问机制移植.md](docs/提问机制移植.md)。**那笔账已经测过了**——[第二轮差分](docs/差分测试-第二轮结果.md)里，多花两轮的预测是错的（实测净 0），重述的账是正的，**前提确认没测出价值，只能算兜底**。

### 知识库

**任何行业、任何事，要过的闸只有四道**——[gates.md](references/gates.md) 把它们和"我们覆盖到哪"逐格摆出来：

| 闸 | 问的是 | 覆盖 |
| --- | --- | --- |
| **人** | 这个人能不能做 | 编制/公职、在校学生、在职副业、职务成果、个人接单的税；**医生律师会计师没有** |
| **事** | 这件事要不要许可 | **20 个门类、97 个大类**的法律和行政法规逐字原文，加 13 张横向规则卡；**部门规章和地方规定没抓** |
| **地** | 在哪个渠道上线 | 类目表逐栏核过的**只有微信小程序**；抖音核过用户协议几条；美团、小红书、快团团、淘宝拼多多只有法规路由，**平台规则没核到** |
| **钱** | 钱怎么收、要不要办执照 | 市场主体登记、「零星小额」那条线的原文、税务登记、收款码、小规模纳税人、发票 |

**内容永远不全，框架必须完整。** 没覆盖的那一格照样告诉你"要过这道闸、大概要什么、去哪儿查"——**那比"我不知道"有用得多**。`check_rules.py` 按闸门把覆盖度打出来，照实写覆盖了什么、没抓什么。

知识库分三层，都在 `references/knowledge/`：

| 层 | 有多少 | 管什么 | 保质期 |
| --- | --- | --- | --- |
| 门类骨架卡 | 20 张，97 个大类都有一格 | 这一行要不要许可：法律、行政法规逐字原文 | 90 天 |
| 横向规则卡 | 13 张，外加平台卡 3 张、钱卡 1 张 | 横跨很多行的：网络交易、直播、广告、个人信息、生成式 AI、食品网络销售、预付式消费、电商登记、主体资格、商业特许经营、健康证、价格和明码标价、定金订金押金 | 90 天 |
| 深卡 | 29 张 | 这一行谁在做、收多少钱、常见死法、「算没答」在这一行长什么样 | 180 天 |

深卡做了零售、餐饮、居民服务、美业健康、教育、互联网技术六行（清单见 [00-索引](references/knowledge/00-索引.md)）；内容电商、文旅、出海等 12 张还没做。

**怎么用**：诊断时先把项目拆成「做什么事 / 在哪个渠道 / 怎么收钱」，每块跑 `kb_lookup.py`，**只读命中的那几节**——全品类的库不能整份读进对话，那本身就会拖慢每一轮。拆开查是因为交叉品类的风险大多出在横向规则上：「宠物上门 + 小程序 + 次卡」最先要补的是预付式消费的书面合同，不是宠物那一行的许可。

**知识库只在开发阶段更新**：抓一手源、逐字核过再发版，不在用户对话里现搜现用。运行时联网只补这一次诊断的缺口，结果不进库。

**每条都标档位**：

| 档位 | 标准 | 现在 |
| --- | --- | --- |
| 规则 | 逐字原文 + 拉取日期 + 来源链接；抓不到的标 `待证`，不逐字引、不报金额 | 252 条，待证 2 条（都是平台规则：页面是脚本加载的，抓不到） |
| 公开数据 | 上市公司公告和年报、政府统计、平台官方公布，带来源和日期 | 深卡表格 274 行 |
| 行业报道 | 媒体报道，只作参考，不拿它下结论 | 深卡表格 241 行 |
| 经验估计 | 每次都说是估计、依据是什么 | 只写在深卡的文字里，不进表格 |

深卡的每个数在开发工坊里都有一张证据表（原文件、行号、原文），**逐行核过才进库**；搜索摘要里的数不收，媒体转述的上市公司数字不当公开数据。**上市公司整体的毛利不等于一家小店的毛利**，卡里的口径栏都写着。

规则举几条（每条都带逐字原文、拉取日期、来源链接）：

- **主体资格**：教师〔2015〕5号（在职中小学教师六条严禁）；劳动合同法 39 条第（四）项（**在职期间真正会用上的是这条，不是竞业**）；计算机软件保护条例 13 条（做软件用这把尺，不是专利法）
- **预付式消费**：消保法实施条例 22 条，**收预付款必须订立书面合同**，个体户在内——这一组的用户往往已经在违规状态里，要给的是"今晚就能补上"
- **商业特许经营**：企业以外的单位和个人不得作为特许人；放加盟要**至少 2 个直营店、经营超过 1 年**——「先招几个加盟商、用加盟费开第一家店」这条路原文直接堵住
- **价格**：不得收取任何未予标明的费用；划线价没写明是什么价的，不得高于前七天内的最低成交价；「退一赔三」原文是三倍、不足五百元按五百元
- **定金**：不得超过主合同标的额的 20%；写成「订金」「押金」又没约定是定金性质的，**不适用定金罚则**

`check_rules.py` 按档位算保质期，报出过期的、`待证` 的、档位写错的。

**它不回答「这条法规还在不在」。** 它量的是拉取日期——"我们多久没抄过它"。第四轮差分撞到了后果：规则库里一条 2023 年就被废止的规章，在它眼里一直是新鲜的、报绿。口径已经改成「📅 拉取日期在保质期内」并明写这两件事不是一回事，**但脚本本身没法知道一条法规活着没有**——那只能靠刷新时回一手源。

**覆盖不到的就说不知道并给查询入口**——每张卡末尾都列了「这一组没覆盖的」。编一条听起来合理的资质要求，是这个技能定义的最严重失败。

### 失败模式库

16 条**机制**，不是死掉的公司名单。每条必须有：诊断测试（能从六问答案直接回答）、为什么致死、**反例**（谁有这个病却活下来了，靠什么）、出路。

**没有反例的机制不入库。** 失败案例库只收录失败者，没有分母——不强制找反例的话，每条都会长成"这样做会死"，而真相往往是"这样做很难，但有人靠 X 做成了"。

## 开发

```bash
python3 scripts/test_scripts.py   # 150 条回归，每条对应一个真实发生过的 bug
bash scripts/mutate.sh            # 变异测试：回滚每个修复，确认测试真的抓得住（81 条，约 25 分钟）
python3 scripts/check_rules.py    # 规则和知识卡的保质期、待证、档位
bash scripts/pack.sh              # 打发行 zip（工作区脏会拒绝）
```

**测试全绿不等于测试有效。** 这套里曾经有三条摆设用例——测的场景已经被别处的修复顺手挡掉了，把对应修复回滚它照样绿。变异台就是用来证明"这条测试在代码坏掉时真的会红"。加了新测试就把对应的变异也加进 `mutate.sh`。

累计修过 20 多个 bug，全部来自实测或对抗评审，没有一个是想出来的。
