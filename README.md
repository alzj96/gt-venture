# 创业诊断 · startup-diagnosis

面向中国创业者的项目诊断技能。在动手之前把项目问清楚，指出在中国做这件事要过哪几道闸，把结论存档以便下次接着聊。

跑在 **WorkBuddy**、**豆包**、**Claude Code** 上，同一套 `SKILL.md`，不用改。

安装见 [INSTALL.md](INSTALL.md)。

---

## 它做什么

两种模式，是两个产品不是详略版：

| | 轻量筛查 | 全面诊断 |
| --- | --- | --- |
| 回答 | 这事儿有没有**明显硬伤** | **该不该做、怎么做** |
| 做什么 | 三项一票否决检查 | 六问 + 失败模式 + 两组闸门 + 对抗评审 + 报告 |
| 轮次 | 4-6 | 15+ |
| 结论 | 发现硬伤 / **未发现硬伤（≠ 可以做）** | 做 / 改了再做 / 不做 |

档案共用，可从筛查升级到诊断，答过的不重问。

---

## 它和"找个 AI 聊聊创业想法"差在哪

我们跑过对照实验：同一份人物剧本，一边走这个技能，一边走一个没有技能的通用助手，还有一边走 gstack 的 `/office-hours`。结论写在 [docs/差分测试-第一轮结果.md](docs/差分测试-第一轮结果.md)。

**诚实的结论是：不在"知道得更多"。**

在规则库覆盖不到的领域，我们和对照组的中国知识同源——都来自模型和联网。差别在三处：

**一、合规核查是制度不是运气。** 对照组做了合规核查，但那是模型自己想起来要做的（10 次检索里 9 次是自主判断）。我们的指令写死了要做，而且写死了怎么做。

**二、主体资格优先于类目资质。** 「我老婆是小学数学老师，她手上有 40 个家长」——用户认为的核心资产正是项目的违法点。只查类目会给出一个引用规范、来源清晰、却完全答偏的结论。那比说不知道更危险。

**三、规则带一手源原文、拉取日期和链接。** 模型能告诉你"可能需要办证"，给不了你逐字原文和它是哪天核对的。

### 规则库

**16 条，每条带一手源原文、拉取日期、来源链接**，例如：

- 教师〔2015〕5号六条严禁（在职中小学教师）
- 教基厅函〔2018〕102号（推荐 APP 受限，**与收不收费无关**）
- 教育部令第53号（校外培训行政处罚，**明确适用于自然人**）
- 教技厅〔2019〕3号（教育 APP 备案，**第十条点名小程序**）
- 微信小程序类目与资质、常见拒绝情形

`check_rules.py` 会报出超过 90 天没核对的条目，以及标着 `待证`（尚未双源互证）的条目。

**覆盖不到的行业就说不知道并给查询链接**——规则库里明写着哪些没覆盖。编一条听起来合理的资质要求，是这个技能定义的最严重失败。

### 失败模式库

14 条**机制**，不是死掉的公司名单。每条必须有：诊断测试（能从六问答案直接回答）、为什么致死、**反例**（谁有这个病却活下来了，靠什么）、出路。

**没有反例的机制不入库。** 失败案例库只收录失败者，没有分母——不强制找反例的话，每条都会长成"这样做会死"，而真相往往是"这样做很难，但有人靠 X 做成了"。

## 开发

```bash
python3 scripts/test_scripts.py   # 52 条回归，每条对应一个真实发生过的 bug
bash scripts/mutate.sh            # 变异测试：回滚每个修复，确认测试真的抓得住
```

**测试全绿不等于测试有效。** 这套里曾经有三条摆设用例——测的场景已经被别处的修复顺手挡掉了，把对应修复回滚它照样绿。变异台就是用来证明"这条测试在代码坏掉时真的会红"。加了新测试就把对应的变异也加进 `mutate.sh`。

累计修过 20 多个 bug，全部来自实测或对抗评审，没有一个是想出来的。

## 一条使用前提

**这个技能不构成法律、财务或投资意见。** 涉及资质、备案、税务的结论请以主管部门或专业人士的意见为准。规则可能已变更，每条规则的核对日期见正文。

它绝不会给出"不需要办证"这类否定结论——说错"需要办"，你白跑一趟；说错"不需要办"，你可能已经上线了才发现违规。两种错的代价差着量级。
