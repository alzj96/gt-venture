# 第一次真实宿主实跑：WorkBuddy + 免费 Hy4

2026-09-16。**在此之前，这个技能所有的行为证据都来自子代理模拟**——四轮差分、82 条回归、38 条变异，全是我们自己跑自己。这是第一次在真实宿主上端到端跑完一次诊断。

**条件**：WorkBuddy 5.5.6 / Free 套餐 / **Hy4 preview（免费档）** / 本机安装 / 11 轮对话 / 王姐社区团购案例（我扮用户）。

## 一、积分：挂了五轮的那个约束不存在

| | 余额 | 本轮 |
| --- | --- | --- |
| 起始 | 2,100 | — |
| 第 1 轮后 | 2,099.02 | **−0.98** |
| 第 2 轮后 | 2,099.02 | −0 |
| **全程 11 轮跑完** | **2,099.02** | **再没动过** |

中间包含**一次联网查竞品**、十几次脚本调用、**一次对抗评审子代理**。**整场诊断不到 1 积分。**

那 0.98 是一次性的（首条消息或某次工具），**边际轮在免费档不计费**。

### 这条的代价要记下来

从第一轮差分到今天，**五轮里每一轮都在为"积分可能不够"做取舍**：把 premise-check 拆出去按需读、给 failure-modes 加索引、ai-era 做成按需读、反复计算"多读 7,900 字值不值"、甚至准备把 SKILL.md 那 24,085 字符瘦身。

**那是在解一个不存在的问题。** 文件小、结构清楚本身是好事，但驱动它们的理由是假的——**我们用五轮在一个没测过的假设上做权衡，而测它只花了二十分钟**。

这比积分数字本身更值得记：**有一个能实测的关键未知时，先去测，不要先围着它设计。**

## 二、三个部署风险一次出清

| 风险 | 结果 |
| --- | --- |
| **怎么安装** | **把目录丢进 `~/.workbuddy/skills/` 就能调用。** UI 的「Installed」列表只列从市场装的，文件系统丢进去的不显示——**我曾据此误判"不认"，那是把 UI 搜索结果当成了加载状态** |
| **宿主让不让跑脚本** | 日志：`archive.py --workspace "…"` → `outcome=sandbox-success`、**`prompted=false`**。沙箱直跑，不弹权限 |
| **档案写哪儿** | `--workspace` 正确指向会话工作区 `~/WorkBuddy/<时间戳>/`，**技能安装目录全程干净** |

第三条尤其值得记：**「两个目录，别搞混」那套纪律在真实宿主里是有效的**——那是这个技能历史上最严重的静默 bug，在真实环境没复现。

## 四、逐条点着的机制

| 机制（哪一轮加的） | 实跑表现 |

| **「付给谁」**（四） | 问出「钱进我自己微信收款码，不走店里收银」，**并把它路由进第四道闸（钱）**，说「现在不展开，免得把后面的问题带偏」 |

## 五、它自己想出来的东西（这些不是 skill 的功劳）

归因要诚实。下面几条**剧本里没有、skill 文件里也没有**，是模型自己的判断：

- **把项目重新定性**：从三个客户名字里看出共同点——「陈阿姨每周两袋米、小李每周要奶、张老师问能不能固定周三送，**这三个人要的不是"下单"，是"周周照订"。你这件事真正的形状不是团购，是周期订**」
- **抓到一个真矛盾**：「你最值钱的客户是**不会用 App 的老人**，而你要做的是一个要他们会用 App 的东西」
- **自己加的一问**：「上个月错的那两回，是群里打字那批还是电话那批？前者小程序能治，**后者换个前端错不到它**」

**所以这一跑证明的是"skill 的结构在免费模型上跑得住"，不是"skill 造出了这些洞察"。** 结构提供的是纪律和顺序；洞察来自模型 + 用户的答案。

## 六、缺陷（扣除后再读上面）

1. **我扮的用户，而且我答得太好。** 三个客户的名字住址周期、单量客单价月流水占比、出错次数与归因——**真实的王姐不会这么答**。这份运行展示的是"答得好时它能走多深"，不是平均情况。
2. **n=1，单案例。** 而且是我们自己的老案例。
3. **只测了全面诊断。** 副业体检和轻量筛查的报告骨架（当天新写的）没有在真实宿主上跑过。
4. **没测断点续跑。** 第 0 步读档案、复述、接着问——这条路径真实环境下没验证。
5. **积分只测了一档模型。** 换付费档或换模型，账完全不同。

按价值排：
