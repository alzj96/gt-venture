# 第五轮对比 gstack：这次比的不是诊断质量，是产品形态

2026-09-15。前四轮（[一](差分测试-第一轮结果.md)／[二](差分测试-第二轮结果.md)／[三](差分测试-第三轮结果.md)／[四](差分测试-第四轮结果.md)）比的都是**同一个项目两边诊断得怎么样**。那条线已经问出结论了：差值在纪律不在知识，对抗评审四轮蝉联，而我们和它在通用能力上没有系统性差距。

**这一轮换个问题**：gstack 已经很成熟，它凭什么让人**一直用下去**、凭什么**值得一直更新**、它和它作者的其他东西是怎么连成一条线的。因为我们要的是同一件事——技能是入口，社群是终点。

---

## 一、它的核心是一份信念清单，不是一堆流程

`ETHOS.md`，169 行，开头第一句：

> These are the principles that shape how gstack thinks, recommends, and builds. **They are injected into every workflow skill's preamble automatically.**

三条编号原则（Boil the Ocean / Search Before Building / User Sovereignty），外加 The Golden Age、How They Work Together、Build for Yourself 三段框架。**每条正文末尾一行 `Read more: https://garryslist.org/posts/...`** ——链回作者自己的博客。

而且它在仓库里是**受保护的**。CHANGELOG 里有一条写着：

> ETHOS.md, promotional material, and Garry's voice are explicitly protected from modification without user approval.

**这三件事拼起来就是它的产品形态**：

1. **信念是产品，技能是信念的可执行形式。** 你装的不是一堆命令，是一个人的干活方式，被做成了能跑的东西。
2. **信念自动注入每一次运行。** 所以你用第十次和第一次，感受到的是同一个人在说话。
3. **信念链回长文。** 技能是入口，文章是深度——**漏斗在 ETHOS 文件里就完成了**。

**这一条是这一轮最直接可抄的。** 我们原来没有 ETHOS：SKILL.md 里散着一堆"为什么这么做"，但没有一处把立场收拢成一份可以单独读、可以被反驳、可以链回长文的东西。

---

## 二、更新本身就是它的卖点

- `VERSION`：**1.87.0.0**
- CHANGELOG 里 **437 个版本条目**
- 最近一版 **2026-09-11**，四天前

而且 CHANGELOG 的写法值得单独学：**它写的是"你现在能做什么"，不是"我改了哪个文件"**。随手一条：

> `/cso` now distinguishes verified vulnerabilities from hypotheses and coverage gaps, and qualified comprehensive audits can produce replayable repair bundles without changing your working branch.

主语是用户，动词是能力。**Added / Changed / Fixed / Security 分节，每条都能被单独读懂。**

对我们的含义很直接：**"持续更新"不是承诺，是要被看见的**。更新记录本身就是"这东西活着、有人在管"的证据，而这正是一个陌生人决定要不要第二次打开它的依据。

---

## 三、它的复利做在个人层，这是它的边界也是我们的机会

第一轮就得出过这个结论，四轮之后仍然成立：gstack 的 `learnings.jsonl`、builder profile 全部写在 `~/.gstack/`，**只有你自己搜得到**；跨人的通道只有遥测，而遥测的事件白名单写死在数据库迁移里（`skill_run` / `error` / `attack_attempt`），官方声明 never sent 的包括 prompts 和任何用户内容。

**那是产品分析，不是知识积累。** 用户越多，**作者**知道得越多；B 用户不会因为 A 用户用过就拿到更好的 skill。

这不是疏忽，是性质决定的：**gstack 的知识是代码，代码在各自的仓库里，天然不可共享。** 你在 auth.ts 踩的坑对我没用。

**我们不同：知识是外部规则，对所有人是同一份。** 一条"收预付款必须签书面合同"，对咖啡馆和理发店是同一条。所以"越用越好"在我们这里可以成立——**但那要靠作者侧持续发版，不靠用户侧自动积累**（理由见 [复利回路移植方案](复利回路移植方案.md)）。

## 四、三处性质不同，决定了不能照抄

| | gstack | 我们 |
| --- | --- | --- |
| **卖什么** | 一个成功的人**怎么干活** | 一件事在中国**能不能干** |
| **可信度从哪来** | 作者本人的成绩（你信他，所以信他的流程） | **一手源 + 可证伪条件 + 公开的实验记录** |
| **错的代价** | 代码写得不够好，可改 | **用户违规上线，或者带着错判断投入半年** |

第二行是关键：**我们没有"因为我很成功所以听我的"这张牌，也不该去打**。用户是第一次创业的人，他没有能力判断你成不成功，他只能判断你说的话经不经得起查。

所以我们的 ETHOS 立信只能靠两样：**每条信念都带"什么能推翻它"**，以及**把实验记录全部公开——包括我预测错的那几次**（第二轮的轮次预测错了、第三轮的"三种形状全在供给侧"错了，两次都白纸黑字写在 docs 里）。

**这比"我很成功"更适合我们的用户**：他信的不是人，是你敢把自己错在哪写出来。

第三行决定了另一件事：gstack 可以"Boil the Ocean、完整性是廉价的"，**我们不能**。我们的默认动作是**不知道就说不知道**，因为这里多写一句的代价是用户照着去办证或者上线。

**没抄 ETHOS 的自动注入。** gstack 把 169 行信念塞进每个 skill 的 preamble，我们按积分计费的宿主上这么干是纯烧钱。折中：SKILL.md 里放 10 行、指向全文，**操作性的部分拆进按需读的 reference**。

## 六、诚实记账：我们现在还缺什么

- **没有作战记录。** gstack 有 437 个版本和一个创始人的名字，我们有四轮差分测试。**差分记录是我们目前唯一的"这东西活着"的证据**，所以它必须继续做，而且必须公开。
- **没有更新节奏。** 现在是"想起来就改"。要让人相信它会一直更新，得有一个可见的节拍——哪怕是每月一条"规则库刷新了什么"。
- **没有社群。** 技能是入口，但入口后面现在是空的。
- **《基准真相》还没有公开地址。** `ETHOS.md` 末尾那行链接现在是 `<待补：发布地址>` ——**这个漏斗现在断在最后一步**。文章不公开，ETHOS 就只是四条没有出处的断言。
- **积分基线仍然没测。** 四轮了。这是唯一一个反复欠着的关键未知。
- **kill criteria 没变**：5 个试用者跑完后复用率为 0 且无人说"改变了某个决策"，这条路就不成立。

---

## 一句话

gstack 让人一直用下去，靠的是**一份被自动注入每一次运行的信念，加上一条看得见的更新节拍**。这两样我们都能做，但立信的方式必须换——**它靠作者的成绩，我们只能靠可证伪条件和公开的错题本**。
