# 从 gstack 抄提问机制：第二轮看的是「问题本身」

2026-09-15。第一轮差分测试（见 [差分测试-第一轮结果](差分测试-第一轮结果.md)）只抄了一个机制：**对抗评审**。那一轮的注意力全在"结论对不对"上。

这一轮看的是另一件事：**gstack 在过程中不断抛出来的那些问题，本身就在帮用户想清楚方向。** 它的价值不在采集到了什么信息，在于用户被问完之后，脑子里的项目和进来时不是同一个了。

---

## 一、核心观察：它让用户「纠正」，我们让用户「生成」

把两边的提问放在一起看，差别不在问得狠不狠，在**要求用户做的动作是哪一种**。

| | 我们（旧） | gstack |
| --- | --- | --- |
| 六问 / 六个 forcing questions | 开放提问，用户从零生成答案 | 同上（这一半是一样的） |
| 决定要不要征求意见时 | 没有对应机制 | `AskUserQuestion` 每次都是**决策简报**：ELI10、赌注、推荐、每个选项的 ✅/❌、Net 一句话收口 |
| 写方案之前 | 无 | **Phase 3 Premise Challenge**：把结论踩的前提列成 1/2/3，让用户逐条 agree/disagree，不同意就回头 |
| 给方案时 | 一个结论 | **Phase 4（MANDATORY）**：2-3 条路线，各带 Effort/Risk/Pros/Cons，外加一条明确推荐，然后 STOP 等用户选 |

**后三行有一个共同点：用户拿到的是一个可以被推翻的东西，不是一个待填的空。**

一个还没想清楚的人，生成很难，纠正很容易。问他「你的用户是谁」，他给你一个标签；把「给三年级学生的家长」摆到他面前，他会立刻说「不是家长，是老师」。那一句纠正里的信息量，比三轮开放提问都大。

这就是这一轮移植的全部主线。已写进 SKILL.md 的「让他纠正，不要让他生成」一节，和它下面的三处落点。

---

## 二、抄了什么

| gstack 的机制 | 我们做成了什么 | 为什么要改形态 |
| --- | --- | --- |
| Phase 3 Premise Challenge | **第 2.5 步前提确认**（[premise-check.md](../references/premise-check.md)） | 加了两样 gstack 没有的：每条标〔你说的〕〔我查的〕〔我推的〕，并点名哪条最要命。理由见第四节 |
| Phase 4 强制 2-3 条路线 + 推荐 | **报告里的「我否掉了什么」** | gstack 的选项是技术实现（用户有能力选）；我们的是"该不该做"（用户没能力在三条商业路线里选，给菜单就是把活推回去）。所以只保留"看得见被否掉的路"，结论仍然只有一个 |
| Q1 之后的 reframe（"Let me try restating what you're actually building"） | **第 0.5 步重述**，提到六问之前 | gstack 放在 Q1 之后；中国用户开场第一句通常是「我想做一个 XX 小程序」——那是形态不是事，不先拆掉能空聊一小时 |
| Smart routing by product stage | **六问的阶段表**（四种状态问不同的组合） | 加了一条铁律：**第 6 问永远不跳**，它是主体资格浮出来的地方。国外框架没这条，因为那儿没有编制 |
| Smart-skip（前面答过的不再问） | 同名机制，**但强制两件事**：跳过要说出来、跳过的内容要存档 | 不存档的话档案显示「已答 3/6」，下次回来重问一遍——smart-skip 会亲手造出这个技能最该避免的失败 |
| Calibrated acknowledgment（"别停留，最好的奖励是更难的问题"） | **六问的「答得好的时候，别停下来夸」** | 补了一条 gstack 没给的理由：表扬会让用户开始为了拿好评回答，后面几问的答案质量立刻下降 |
| Anti-Sycophancy 禁语表 | **说话方式里的中文禁语表** | 直译不能用。中文的附和长成「这是个挺有意思的方向」「看你自己的情况」，和英文那几句不是同一批 |
| Escape hatch（用户要跳过时推一次再放行） | **用户要跳过流程时：推一次，只推一次** | 旧版直接「尊重它」，放弃得太早。用户说"别问了"时要的是快，不是差——一次都不推等于默认他知道自己在放弃什么 |
| "End with the assignment" + builder profile 的 journey 跟踪 | **第 0 步的「上次的下一步必须回访」** + `上次的作业做了` 信号 | gstack 记 assignment 是为了分层收尾；我们拿它闭环——不回访的话，报告结尾那三条就是摆设，而用户会发现 |
| Phase 4.5 Founder Signal Synthesis | **`pattern.py signal` 六类正向信号 + `强项.md`** | gstack 拿信号去分层收尾话术，我们拿它修一个自己造的伤：模式库七类全是毛病，第三次回来的人面对的是一份罪状清单 |

## 三、没抄什么

| 没抄的 | 理由 |
| --- | --- |
| 决策简报的完整模板（ELI10 / Completeness N/10 / Net / 40 字下限） | 宿主（WorkBuddy、豆包）不一定有 AskUserQuestion；更重要的是，**一个第一次创业的人面对带 `Completeness: 8/10` 的表格会直接不答**。只取了三条能在纯文字聊天里跑的：先给推荐、每个选项写清放弃什么、让他回一个编号 |
| 「5+ 选项要拆成链，绝不丢弃」 | 我们反过来：**选项超过三个是你没想清楚，不是他选择多。** gstack 的用户在挑技术方案，选项多是真的多；我们的用户在挑要不要干这件事 |
| `question-preference` 行为级自调优 | 理由在 [复利回路移植方案](复利回路移植方案.md) 里写过，这次复核依然成立：gstack 调的是"要不要征求意见"，我们调的是"要不要逼问"，而**用户说「别问了」恰恰是最该继续问的信号**。这次只抄了它的"推一次" |
| 分层收尾（Garry Tan 的信、申请 YC） | 第一轮就定过：抄机制可以，抄话术会死 |
| telemetry / question-log 回传 | 我们没有回传通道，现在也不该有 |

## 四、三条本土化（国外框架不会写的）

**一、标出处 + 问「哪里不对」。**
gstack 的 Phase 4.5 把 "Pushed back on premises" 当成正向信号来数——**它默认创始人会反驳**。我们的用户不会：第一次创业的人、年纪比你小的人、花钱来问你的人，默认姿势都是同意。所以摆出去的每一条都要标是谁说的（不标就只能整体点头），问法也要从「对不对」改成「哪个词用错了」。**沉默和「对对对」不算确认。**

**二、「有关系能办下来」要和一张证一样被核实。**
六问文件新增的第六组追问对照。这是中国特有的一种"已解决项"错觉，最常见的漏法是听到之后接一句「那就好」然后往下走。要追三样：那条关系管哪一环（受理/审批/发证）、管不管这个类目、关系断了项目还在不在。**把「有关系」当成「已办好」写进报告，和编一条资质要求是同一类错误。**

**三、阶段路由可以跳任何一问，但第 6 问永远不跳。**
主体资格是唯一一个能把已经跑起来的项目直接掐掉的东西，而它是从第 6 问里浮出来的。

## 五、这笔账目前是负的，而且没被测量过

诚实记账。**轮次**：

| 改动 | 轮次 |
| --- | --- |
| 第 0.5 步 重述 | **+1** |
| 第 2.5 步 前提确认 | **+1**（被推翻时再 +1） |
| 阶段路由 | −1 ~ −3（只对已有用户/已收钱的项目生效） |
| smart-skip | 0 ~ −2 |
| 跳过流程时推一次 | +0 ~ +2，且只在用户主动要跳时发生 |
| 正向信号 | 0（脚本调用，不占对话轮） |
| 回访上次的「下一步」 | **+1**，但只对回头客发生，而且它换来的是这次对话里唯一的新证据 |

**大多数用户是"还没做出东西"那一档，对他们净 +2 轮**（15 → 17）。阶段路由省下来的轮次给的是另一批人。

**上下文**（全面诊断一次要读进去的核心几件）：

```
旧：SKILL.md 34,930 + six-questions  7,075 + report-format 3,366        = 45,371 字节
新：SKILL.md 47,352 + six-questions 13,073 + report-format 4,957
    + premise-check 3,709                                              = 69,091 字节   (+52%)
```

中文 UTF-8 三字节一个字，约多读 7,900 字。**在按积分计费的宿主上，这是真金白银。**

抵消措施只做了一个：前提确认的细节拆进了 `references/premise-check.md`，只有走到那一步才读（轻量筛查和副业体检完全不碰它）。

**没有证据，不给判断——这条对我们自己也成立。** 上面这笔账里，"重述能省掉后面三轮"和"多读 7,900 字值不值"都是推断，不是测量。

> **已测。结果见 [差分测试第二轮结果](差分测试-第二轮结果.md)。**
> **轮次那一栏的预测（+2）是错的**，实测净 0——案例一 −1、案例二 +1。把新增步骤静态相加，漏掉了"第 1 轮把方向拨对，后面就不在错的对象上绕"。
> **重述的账是正的**（花 1 轮买回 6 轮）。
> **前提确认没测出价值**——案例一它拿到的关键事实，旧版在第 4 轮就自己追出来了；案例二零产出。它的价值是**兜底**不是**新增**。
> 两个都留着，但期望要降。下面三条里第 1 条（积分基线）仍然欠着，第 2、3 条已执行。

原计划的下一步：

1. 在 WorkBuddy 里手动跑一遍完整六问对话（不装 skill），记总轮次和积分——这是一直欠着的基线
2. 同一个人物剧本，跑新旧两版，比**轮次**和**结论差异**：如果重述和前提确认一次都没改变过方向，那它们就是纯成本，该砍
3. 砍的时候先砍第 0.5 步（它面向所有人，成本最高），留第 2.5 步（它只在全面诊断里发生，而且防的是最贵的错）

## 六、一句话

第一轮学到的是**合规核查在我们这里是制度，在 gstack 那里是运气**。这一轮学到的是反过来的一件事：**gstack 的提问是制度，我们的提问是六道开放题。** 开放题问得再狠，用户也得从零生成；摆一个具体到刺眼的句子让他推翻，他一句话就能把方向拨回来。

代价是每次诊断多两轮、多读七千字。**这笔账下一步就去测，测不回来就砍。**
