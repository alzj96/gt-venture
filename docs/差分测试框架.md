# 差分测试框架：我们和 gstack 的差异必须能归因

用来回答一个问题：**我们的 skill 到底强在哪，还是只是不一样。**

起因是一个方法论判据：同一个创业项目，走我们的 `/创业诊断` 和走 gstack 的 `/office-hours`，结论应该接近。**有差异就必须能归因**，而合法的归因只有一种——我们有 gstack 没有的知识体系（中国法律、财税、平台规则）。归不到那里的差异，要么是我们在通用能力上莫名偏离，要么是噪声，两种都是缺陷。

这比任何评审打分都硬，因为评审给的是意见，差分给的是证据。

---

## 一、为什么不比"分数"

gstack 的 office-hours 出设计文档，我们的创业诊断出诊断报告，两边都不打分。所以"分数接近"要翻译成可测的东西：**结论是否一致**。

固定六项，两边用同一个模板收尾：

| 项 | 为什么测它 |
| --- | --- |
| 该不该做 | 最粗但最重要的一致性检验 |
| 最窄楔子 | 考验有没有真的听懂业务 |
| 三个最大风险（排序） | 排序比列举更能暴露判断差异 |
| 下一步三件事 | 可执行性，空话在这里现形 |
| **中国特有约束**（逐条带文号/来源） | **护城河的量化位置** |
| 通用判断 | 对照组，这一栏本该两边相同 |

第五栏是整个实验的重心，第六栏是它的对照。

---

## 二、只比结论不够，要比过程

结论相同不代表路径相同，而**路径决定了这个优势能不能复现**。同样说出"在编教师不能推荐 APP"，一个是从规则库里读到的（可复现、可维护、可更新），一个是模型碰巧记得（下个版本可能就忘了）——前者是资产，后者是运气。

所以每条路线还要产出一份统一格式的过程记录。

### 逐步流水账

| # | 动作 | 工具 | 依据 | 产出的关键信息 | 是否改变后续方向 |

**依据**只能三选一，这一栏决定了哪些行为是 skill 带来的：

- `skill指示` —— skill 文件明确要求（注明文件与小节）
- `自主判断` —— skill 没说，模型自己决定
- `用户触发` —— 用户的回答逼出来的

`自主判断` 占比高说明 skill 的指导密度低，模型在自由发挥；比例的变化也是 skill 迭代效果的一个指标。

### 信息来源归因（最关键）

| 结论要点 | 来源 | 具体是什么 |

来源四选一：`skill内置` / `联网查得` / `模型内在知识` / `用户提供`。

**这一栏天然会被高估成 `skill内置`**，因为模型确实读过那些文件，读完再作答时分不清自己本来知不知道。所以必须给一个反事实判据：

> **假如 skill 里没有这条，你还会不会说出来？**
> 会 → `模型内在知识`，哪怕 skill 里也碰巧有。

没有这个判据，实验会得出一个虚假的护城河——那比没做实验更糟，因为它会让人放心。

### 统计

轮次、工具调用总数与分布、实际发出的联网查询词、`skill指示` vs `自主判断` 的步骤数。

查询词要逐条记，因为它同时是**出网脱敏规则的实测**：查询词里出现人名、群名、学校名，说明那条规则没被执行。

## 三、案例怎么选

**至少两个，一个已调过、一个全新**，用来控制过拟合。

- **已调过的案例**：我们在它上面修过 bug、调过规则库。它上面的优势有多少是真的、有多少是拟合出来的，只有和全新案例对比才知道。
- **全新案例**：双方都没见过，而且**故意选在我们规则库覆盖不到的领域**。这一格的结果最有信息量：如果没有规则库加持时我们和 gstack 结论一样，那就证明**优势完全来自规则库**——这是个有用的坏消息，它直接告诉你规则库该往哪几个行业扩。

两边必须用**完全相同的人物剧本**，包括被追问时才给出的答案。剧本不同，后面所有比对都是噪声。

---

## 四、怎么读结果

三种情形，含义完全不同：

**情形 A：差异全落在「中国特有约束」那一格**
论文成立。此时再看过程记录：那些约束的来源是 `skill内置` 还是 `模型内在知识`？

- 多数 `skill内置` → 护城河是真的，且可维护
- 多数 `模型内在知识` → **优势不来自我们**，来自模型本身。规则库当下的边际价值接近零，真正的价值要靠它比模型更新、更准、更细（一手源 + 日期戳的意义正在这里）

**情形 B：通用判断也有差异**
先排除剧本执行噪声（重跑一次），排除不掉就说明通用能力上有偏离，该查是哪一步引入的。

**情形 C：gstack 找到而我们漏了**
真缺口。比任何评审意见都硬，优先级最高。

---

## 五、这套东西怎么复用

每次规则库扩了新行业、或 SKILL.md 有结构性改动之后，跑一次差分：

1. 选一个新行业的案例，写人物剧本（六问都要有答案，含被追问才给的那层）
2. 两条路线各起一个子代理，同一份剧本，产出 `结论.md` + `过程.md`
3. 按第四节读结果，把归因表存档
4. 归因表逐次累积，就能看出**护城河是在变厚还是在变薄**

归因表比分数有用得多：分数告诉你"现在几分"，归因表告诉你"下一块砖该砌在哪"。

---

## 六、这套方法的边界

- **两条路线由同一个模型家族执行**，共享同一套内在知识。所以 `模型内在知识` 那一栏在两边是同源的，这是这个实验测不了的部分。真正干净的对比需要不同模型，代价是引入模型能力差异这个新变量。
- **自评归因不可完全信任。** 反事实判据能压低偏差，压不到零。归因表是信号不是判据。
- **n 很小。** 两个案例说明不了统计规律，它能说明的是方向和具体的缺口。别把它当成率来解读。
