**顶层结论三次一致，一次不同**，而那一次的不同源于 gstack 找到了我们漏掉的一条规则。

---

## 结论一：在规则库覆盖不到的领域，我们和 gstack 打平

王姐案例（生鲜，我们的规则库完全不覆盖）：

- **我们**：本案所有中国特有约束的内容都不是 skill 内置的
- **gstack**：结论里 12 条中国特有约束，`skill内置` 来源 **0 条**

**两边的中国知识都来自模型和联网，不来自 skill。**

这直接回答了那个悬着的问题：**规则库的边际价值只存在于它覆盖的范围内，范围之外我们没有内容优势。**

推论很实际：规则库不该追求"全"，该追求"深"和"新"——覆盖到的地方要给逐字原文、日期、来源，那是模型给不了的；覆盖不到的地方老实说不知道，别指望规则库扩成百科。

## 结论二：差别不在指令密度，在指令什么

```
             skill指示  自主判断
edu-gstack      20        20
fresh-gstack    37        16
edu-ours        19         8
fresh-ours      23        10
```

粗看 gstack 的密度不低。但细看：

> （gstack 那边）Phase 2.75 明确规定搜什么（竞品、常见错误、在位者为什么失败），**没有一个字提合规**。10 次合规检索里 **9 次标记为「自主判断」**。

**gstack 指令的是流程，合规那块完全靠模型自由发挥。我们指令的恰恰是那一块。**

所以我们的差值是**行为可复现性**，不是知识量。同一个模型，合规核查在我们这里是制度，在那边是运气。

这个说法比"我们有规则库"站得住，也更难被抄——抄一份 markdown 容易，抄一套让模型稳定执行的指令结构难。

## 结论三：两个案例里，决定性的一步都是联网核实竞品

- 教育：抓竞品官网正文 → 小猿 AI 免费提供拍照批改，用户三个楔子里两个是免费商品
- 生鲜：快团团／群接龙对团长免费，且已内置"接龙汇总 + 按人打印分拣单"——正是王姐点名最烦的那件事

**两次都翻转了结论。** 我们那份的自评说得最直白：

> 没有这一步，我会答对第二重要的问题，漏掉最重要的。**合规是可以绕的（换渠道），免费巨头是绕不开的。**

配套学到一条方法：**搜索摘要不够，要抓正文。** 摘要说"基础功能免费"模糊到可以一笔带过；正文给出和用户楔子逐字对应的功能点。而且**页脚常藏备案号**（`教APP备` / `ICP备`），那是判断"我要不要办同样的证"最快的方法——搜索摘要里没有页脚。

已写进 SKILL.md。

## 结论四：gstack 找到了我们漏的，机制是强制对抗评审

**教育案例**：《校外培训行政处罚暂行办法》（教育部令第53号）第二条明确适用于**自然人**。我们只查了教师侧，结论是"把她从渠道位置上撤下来"——**有说服力，但不完整**，因为创始人本人也是适格主体。

**生鲜案例**：12 条中国约束里 **6 条是评审子代理逼出来的**，另外它还纠正了 2 条用错的法、1 条挂错的法条，以及一个致命的结构性缺陷（布置的作业采不到承诺要算的数），第二轮又揪出验证窗口骑在中秋国庆上。

> 没有这个循环，最终结论会是「引用规范、来源清晰、但答偏」。

**这是这次测试最大的收获。** 已补入我们的第 3 步，并抄了它最关键的一点：**评审只看报告，不看对话**——看了对话会被推理过程带着走，挑不出盲区。

配套防御：评审提的法规问题不直接采纳，回一手源再定。两次测试里评审各给错过一个文号。

## 实验缺陷（必须扣除后再读上面的结论）

### 1. 我污染了对照组

`~/.gstack` 是共享存储。我在本次会话早些时候用 `gstack-learnings-log` 记的一条经验（`eligibility-outranks-license-in-cn-diagnosis`），原文包含"主体资格优先于类目资质"和"教师〔2015〕5号第四、六条"，**被 gstack 的 office-hours 在提第一个问题之前自动注入**。

**教育案例的对照在"主体资格"维度上无效。** 两条路线的 builder profile 也串了。

反过来这证实了 gstack 的复利回路真实有效——一条经验跨会话传递，只不过是以毁掉实验的方式。

**下一轮的做法**：跑 gstack 那条路线前先备份并清空 `~/.gstack/projects/<slug>/learnings.jsonl` 和 builder profile，跑完恢复。

### 2. 教育案例对我们过拟合

`rules-personal-eligibility.md` 开头把老陈这个案例**逐字写成了反面教材**，连两个变通的驳法都预写好了。那一路线的 `skill内置` 计数里有相当一部分是**我把答案抄进去了，不是能力**。

这是我们自己的 agent 主动披露的，没人要求它这么做。

### 3. 两条路线同模型家族

`模型内在知识` 那一栏在两边是同源的，这个实验测不了。真正干净的对比需要不同模型，代价是引入模型能力差异这个新变量。

### 4. n=2

方向和缺口有效，比率无效。

## 顺带发现的 gstack 缺陷（不要抄）

**builder profile 按机器用户存，不按被诊断对象存。** 于是 skill 会对第一次来的王姐说「欢迎回来，上次我们聊的是口算练习」——上一个被诊断的是另一个人。

我们的 `模式.md` / `敏感问题.md` 按工作空间存，比按机器用户好，但**同款风险还在**：一个顾问在同一目录里给多个客户诊断，模式会串。已补：`pattern.py show` 检测到多个项目时出声提醒确认是不是同一个人。

**另一条**：gstack 的收尾是 Garry Tan 个人信 + 申请 YC 的话术。念给武汉超市老板娘，合理反应是「那是什么？国外的？我一个卖菜的……」。**这不是 bug 是定位差异**，但提醒我们：抄机制可以，抄话术会死。
