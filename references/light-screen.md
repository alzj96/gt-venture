# 轻量筛查

**什么时候读这份**：他选了「先来快的」，或者开口就表态只想快速看看。报告骨架在 [报告格式](report-format.md)「轻量筛查的报告」。

## 轻量筛查怎么做

**只做这三项，做完就停：**

1. **主体资格**——听到"我老婆是老师""我朋友在体制内""我自己是公务员"这类，立刻查 [主体资格红线](rules-personal-eligibility.md)。没听到就问一句"你和合伙人里有在体制内或者有执业资质的人吗"。
2. **核心功能是不是已经免费**——问一句"你这东西最核心的那个功能是什么"，然后**联网查有没有人在免费提供**。抓官网正文，不要停在搜索摘要。
3. **付费证据**——问第 1 问，只问这一问。追问最多一次。

   **他已经在收钱了，这一项自动过**，别再问一遍。换成一句「你收的是哪一笔、多少钱、多久了」，把它当成已有事实记下来，省下的力气放到前两项上。

命中任何一条硬伤，**当场说清楚，不要等到最后**。

## 轻量筛查的输出边界（这条不能破）

**永远不要说"看起来没问题，可以做"。**

三项没中，只能说：

> 这三样都没发现硬伤。但**这只是筛查，不是诊断**——我没问你的用户是谁、最小可做到多小、你凭什么是做这件事的人，也没查类目资质和行业规则。想把这些问清楚，我们走全面诊断，你已经答过的不会重问。

理由：轻量筛查查的是**能一票否决的东西**，通过了只说明"没踩到这三个雷"，离"这事能做"差着整个诊断。说"可以做"会让用户带着一个没被验证的判断去投入几个月——**那正是这个技能存在要防的事**。

## 筛查结束前自查（只有三条，但一条都不能破）

- [ ] 没有说过"可以做""看起来没问题""问题不大"这类话
- [ ] 明确说了**这是筛查不是诊断**，并列出了没查的东西（用户是谁 / 最小可做到多小 / 你凭什么 / 类目资质）
- [ ] 三项里查到的每一条，都给了**具体的东西**——法规原文加日期，或竞品名字加它免费提供的功能。没给具体东西的那一项，说"没查出来"而不是"没问题"

第三条最容易破。"主体资格看起来没问题"和"我问了，你们都不在体制内，这一项过"是两句话——**后者是结论，前者是印象**。

## 从轻量升到全面

档案是共用的，轻量筛查答过的直接接着走：

```bash
python3 <技能目录>/scripts/archive.py --workspace "$(pwd)" save --project "<项目名>" --step 1 --answer "<用户原话>"
```

第 1 问在轻量里问过就已经存了，升级时 `find` 会显示"已答 1/6，下一问是第 2 问"。**不要重问。**
