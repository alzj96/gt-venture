# 记下这次的模式

**什么时候读这份**：报告出完、资源对接问完之后（主流程第 5 步）。

## 第 5 步：记下这次的模式

报告出完之后，回看这次诊断里用户表现出的倾向，记一到两条：

```bash
python3 <技能目录>/scripts/pattern.py --workspace "$(pwd)" log --kind <七类之一> --note "<一句话，不含细节>"
```

七类：`高估需求` `说不出人` `楔子砍不动` `优势是通用能力` `跟风` `低估合规` `低估竞品`

**这是这个技能唯一能随时间变强的地方。** 没有它，用户第十次来和第一次来没有区别——而档案只能让你记得聊到哪，记不住他是个什么样的人。

只记倾向，不记项目细节、人名、渠道。这个文件每次诊断开头都会被读进上下文。

没观察到明显倾向就不记，不要硬凑。

**用户改掉了某个毛病，把它下架**：

```bash
python3 <技能目录>/scripts/pattern.py --workspace "$(pwd)" retire --kind <类型>
```

不下架的话它会永远触发提醒，开场白慢慢变成一份罪状清单。判断标准：这一类的毛病在本次诊断里明显没再出现，而且用户主动说了"上次你提醒我之后我去问了"这类话。

### 也要记这次他做对了什么

```bash
python3 <技能目录>/scripts/pattern.py --workspace "$(pwd)" signal --kind <六类之一> --note "<一句话，不含细节>"
```

六类：`说得出人` `拿得出证据` `砍得动` `有一手观察` `反驳过我` `上次的作业做了`

**为什么这条是必要的，不是锦上添花**：上面七类全是毛病。只记毛病的话，一个人来第三次时，开场白就是一份罪状清单——**而这个技能的存亡标准是他会不会来第四次**。

而且正向信号有诊断用途，不只是情绪价值：

- **`反驳过我`** 是最值钱的一条。用户在第 2.5 步推翻过我的前提、并且说得出理由，说明他对这件事有真判断，不是来求个安慰。下次可以问得更硬，也可以少花力气做心理铺垫。
- **`上次的作业做了`** 直接决定下次怎么开场。做了的人，开场该问"上次让你去找的那三个人，聊出什么了"；没做的人，问了只会尴尬，该换成更小的动作。
- **`说得出人` / `拿得出证据`** 连续两次出现，说明第 1、3 问可以问得快一些，把省下的轮次放到闸门上。

`show` 会把正向信号排在毛病前面输出。这是刻意的——**先看到他做对了什么，再看到他反复错的地方，这两句话的顺序会决定他要不要接着聊。**

同样只记倾向，不记项目细节、人名、渠道。没观察到就不记，不要为了好听硬凑——**凑出来的表扬会让真的那条一起贬值**。
