# 开场：分清是哪种事、重述一遍、选深度

**什么时候读这份**：新项目（`find` 没找到这个项目的档案），问第一个问题之前。接着上次的项目读 [接着上次](resume.md)，不读这份。

查完档案**先别问第一个问题**，走第 0.5 步。

## 三种模式

**这一节讲的是怎么选，不是什么时候问。** 时机在第 0.5 步：**先把他要做的事重述一遍，再让他选深度。** 顺序反了，他是在没听到一句准确重述的情况下选产品，只能靠猜。

**先判断用户做的是哪一类事**，再问他要哪种深度。判错了后面全错——六问对接单是不适用的。

### 他还没有一个项目

「毕业想自己做点事，不知道做什么」「想创业但没想好方向」——**手上没有一个能诊断的东西**。这个流程接不住他：第 0.5 步没东西可重述，六问没东西可问。

先用一个选项分清是哪种，别凭一句话判：

```
AskUserQuestion(questions=[{
  "header": "有没有具体的", "multiSelect": false,
  "question": "你现在是心里有一件想做的事、只是说不清楚，还是还没有具体想做哪件事？前一种我们接着往下聊；后一种我先说几句实话，不硬诊断。",
  "options": [
    {"label": "有一件，说不清", "description": ""},
    {"label": "还没有具体的", "description": ""}
  ]
}])
```

- **有一件，说不清** → 正常走第 0 步。说不清本身就是第 0.5 步要处理的
- **还没有具体的** → **不走诊断，不建档案，不替他想点子**

**为什么不替他想点子**：帮人想做什么，是基础模型本来就做得很好的事，写进这个技能剩不下什么（见 [ETHOS](../ETHOS.md)「量一下和基础模型的距离」）。这个技能的用处在判断一件具体的事能不能做、要过哪几道闸。**给他一堆点子，他会挑一个最顺耳的去做，那正是这个技能要防的。**

照实说，给三条怎么找，让他有了一件具体的事再来：

> 你现在还没有一个能诊断的东西——这很正常，大多数人都是从这开始的。我不替你想做什么，想出来的点子你会挑最顺耳的那个，那恰恰最危险。三个找法：
>
> 1. **从你手上有的东西出发**：你会什么、认识谁、在哪儿待过。学生最值钱的往往是离某一群人很近
> 2. **去看身边谁在为一件事花钱，或者花时间将就**：自己搭表格、托人帮忙、忍着不办——那就是需求留下的痕迹
> 3. **记下你自己最近一次为什么事掏过钱、或者骂过**
>
> 有了一件具体的事——给谁、做什么——再来，我们从那儿开始问。

| | 副业体检 | 轻量筛查 | 全面诊断 |
| --- | --- | --- | --- |
| 适用 | **卖自己的时间和手艺**（接单、外包、兼职、小生意） | 有个项目想法，先看有没有硬伤 | 有个项目想法，要结论 |
| 回答的问题 | 能不能做、赚不赚得到、会不会出事 | 有没有**明显硬伤** | **该不该做、怎么做** |
| 做什么 | [四问](side-hustle.md) | 三项检查 | 六问 + 失败模式 + 两组闸门 + 报告 |
| 大概几轮 | 6-8 轮 | 4-6 轮 | 15 轮以上 |

### 怎么分辨副业和创业

**不是看规模，是看卖什么。**

- 卖**你自己的时间和手艺** → 副业体检。"帮人做小程序""接设计单""代运营""周末摆摊"
- 卖一个**能脱离你运转的东西** → 轻量筛查或全面诊断。"做一个小程序卖给很多人"

**分不清就问一句**："你是想接活赚钱，还是想做一个东西卖给很多人？"

用户自己说"副业"但描述的是做产品的，按产品走；说"创业"但其实是接单的，按副业走——**按事情的性质走，不按他用的词走**。

**判成副业**：读 [副业四问](side-hustle.md)，开头写了怎么做（先 `mode --set 副业` 再存）。**选了「先来快的」**：读 [轻量筛查](light-screen.md)。

## 第 0.5 步：把他要做的事重述一遍

问第一个问题之前，先用**一句话**把他要做的事说回去。这一步花一轮，但它经常省掉后面三轮。

**重述不是复读。** 把他的话原样说一遍没有任何价值。价值在于**你替他做了一次具体化，他只需要纠正**——[怎么问](asking.md)「让他纠正，不要让他生成」的两条（标出处、问「哪里不对」）在这里全都适用。

一句话里必须钉死四样：**给谁 / 做哪一件事 / 他拿到什么 / 你靠什么东西做这件事，那样东西是不是你的**。他没说清楚的，你按最可能的猜一个具体的填进去，并标出来那是你填的。

**发法：一次 `AskUserQuestion`，三个问题连着问**——重述、项目名、深度。
**三个必须在同一次调用里**：`mode --set` 和 `save` 都要项目名，名字问晚了，
选完深度该立刻跑的 `mode --set` 就跑不了，第 1 问的答案也存不进去（真机上踩过）。

```
AskUserQuestion(questions=[
  {"header": "我理解的", "multiSelect": true,
   "question": "我先说一遍我理解的：给三年级学生的家长〔我猜的〕，做一个拍照批改口算作业的小程序〔你说的〕，让家长每天省十分钟〔我猜的〕，靠你老婆出题、你写代码〔我猜的〕。哪几句不对？",
   "options": [
     {"label": "不是三年级家长", "description": "〔我猜的〕你只说了「家长」"},
     {"label": "不是省十分钟", "description": "〔我猜的〕你没说省什么"},
     {"label": "不是老婆出题你写代码", "description": "〔我猜的〕你没说谁来做"},
     {"label": "都对", "description": "四句都没问题"}]},
  {"header": "项目名", "multiSelect": false,
   "question": "这个项目怎么称呼？下次接着聊靠这个名字找档案。",
   "options": [
     {"label": "口算批改", "description": "用你描述里最核心的那个词"},
     {"label": "作业小帮手", "description": "……"}]},
  {"header": "诊断方式", "multiSelect": false, "question": "先来快的，还是问透？",
   "options": ["问透（推荐）", "先来快的"]}   // 选项说明见下面「另外两种」那节
])
```

**〔我猜的〕〔你说的〕必须在问题正文里**（上面例子就是这么写的），选项说明里那份是补充——WorkBuddy 上说明不显示，只靠说明标出处，他就看不出哪句是猜的。

**项目名的选项用他自己说过的词拼**，不要自己创作——名字是跨会话找档案的唯一键，你起的名字他下次说不出来。

**「都对」和「不是 XX」同时勾上了**（多选框不拦这个），**按勾了的那几句不对来处理**——他愿意多点一下指出错处，比顺手点的「都对」可信。

**他勾了「都对」，不算确认**（见 [怎么问](asking.md)「用户只会说『对』」）：挑最要命的那一句，下一次调用追一个**只有知情人才答得出的细节**，也做成选项。

**第四样是后加的，因为前三样有一个结构性盲区。** 「给谁 / 做什么 / 拿到什么」三样**全在需求侧**——它们问的是"卖给谁、卖什么"，没有一样碰**供给侧**。

于是这种项目它一个都拦不住：**你要卖的东西不归你、要用的人没答应、要靠的关系还没打招呼。** 实测里有人讲了九轮"我要卖厂里的尾货"，没有一句假话，第十轮才知道厂子是他姐夫的、他没有股份、这事还没跟姐夫提过（见 [差分测试第三轮结果](../docs/差分测试-第三轮结果.md)）。

**多数项目这一样一个词就答完了**（"我自己做"），成本几乎是零。值钱的是答不上来的那几次。

**为什么必须是这个时候**：中国用户开场最常见的说法是「我想做一个 XX 平台 / 小程序 / App」——那是一个**形态**，不是一件事。形态可以聊一小时而毫无进展。把形态换成「给谁做哪件事」，方向偏差在第一分钟就暴露，而不是等到第六问答完、报告写了一半才发现整个前提错了。

**猜的部分不标出来的后果比看上去严重**：用户会默认你听懂了，然后顺着你的版本往下答——**那时候偏的就不只是你的理解，是他的项目**。

**他说不出哪儿不对，也说不出这三样，那这就是第一个发现。** 别硬凑一句漂亮的重述糊过去。照实说：

> 「我说不出来你要给谁做哪一件事——你也还说不出来。这不是坏消息，这说明现在最该做的不是开发，是去找三个人聊。我们接着往下问，这一条我会写进报告。」

**项目名要问，不要自己起。** 在第 0.5 步那一次 `AskUserQuestion` 里问，选项用他描述里的词拼。名字是跨会话找回档案的唯一键，你自己创作的名字下次用户说不出来。**一定要在选深度之前拿到名字**——`mode --set` 要用它。

## 另外两种

**轻量筛查**和**全面诊断**是两个产品，不是同一个的详略版。开场问一句，别替用户决定。

**用户没表态时，调用 `AskUserQuestion`，发完就停，等他点。** 必须是一次工具调用，
**不是把两个选项写成一段话**——写成话他就得打字，而第一次来的人面对一段要他打字回的
选项，最常见的反应是跳过这个问题接着讲别的。

（Claude Code 和 WorkBuddy 都有这个工具，且都不是延迟加载的。它必须出现在 SKILL.md
frontmatter 的 `allowed-tools` 里——**第一次真机验证没弹，根因就是那里漏了它**：
正文说用，许可名单里没有。）

```
AskUserQuestion(questions=[{
  "header": "诊断方式",
  "question": "先来快的，还是问透？问透：六个问题加合规闸门和竞品核实，十几轮，出一份能转给合伙人看的报告。快的：五分钟只查三样一票否决的硬伤——但查不出来不等于能做，用户是谁、最小做多小、你凭什么、要办什么证都不查。",
  "multiSelect": false,
  "options": [
    {"label": "问透（推荐）", "description": "十几轮，出报告"},
    {"label": "先来快的", "description": "五分钟，只查硬伤"}
  ]
}])
```

**哪个标「（推荐）」看情况**：用户一上来就详细讲项目的，推荐「问透」——他愿意讲那么多，
说明他要的是结论不是筛查；开口就说"就想快速看看"的，推荐「先来快的」。
**推荐必须有一个**，没有推荐的选项列表是把活推回去（见[要用户选的时候，怎么摆](asking.md#要用户选的时候怎么摆)）。

**只有调用失败时才退回文字问法**（工具不在列表里、或调用报错）——不是「觉得写成话也行」就退：


> 两种做法。**快的**：我查三样最容易一票否决的东西——你或合伙人有没有身份限制、你的核心功能是不是已经有人免费在做、有没有人真的为这事付过钱。五分钟，能告诉你有没有硬伤，**但查不出来不等于这事能做**。
> **全的**：六个问题问透，加上合规闸门和竞品核实，出一份能转给合伙人看的报告。要久一些。
> 先来快的？

**用户已经表态了就别弹选项。** 「就想快速看看」「随便帮我看看有没有坑」是表态，
「帮我好好分析一下」「我想听结论」也是。这时候直接说你按哪条走，并把放弃的那几样
说出来——**弹一个他已经答过的选择题，和重问一遍已经答过的问题是同一种失礼**：

> 按你说的走**轻量筛查**——只查三样最容易一票否决的。放弃的是：用户是谁、
> 最小做多小、你凭什么、类目资质，这四样都不查。要哪天想问透，说一声。

用户没表态、或者一上来就详细讲项目的，**默认走全面诊断**。

**这个选择题问得再好，也只在他没表态时才该出现。** 选项是用来省他打字的，
不是用来走流程的。

**六问、追问、重述、前提确认全都用选项**（见 [怎么问](asking.md)「默认是选项，打字是迫不得已」）。
六问是事实题，规矩和这里不一样——不标推荐、故意摆出「算没答」的那种、存档标〔选了〕。
见 [六问](six-questions.md)「每一问都用 AskUserQuestion 问」。

**副业体检不进这个选项。** 它是按事情的性质路由的，不是用户点的——
摆成选项等于请他按自己用的词选，而他用的词恰恰常常是反的。
判成副业就直接说出来，留一句让他推翻：「你说的是接单，我按接单这条路走；
如果你真正想做的是一个能脱离你运转的东西，说一声，我们换一条。」

**选定之后先标记**，否则下次会认错：

```bash
python3 <技能目录>/scripts/archive.py --workspace "$(pwd)" mode --project "<项目名>" --set 副业|筛查|诊断
```

不标的话，一次**完成的**轻量筛查在档案里长得像一次**半途而废的**全面诊断（都是「已答 1/6」），下次开场会说"上次聊到第 2 问，接着来？"——而用户根本没打算走全面诊断。
