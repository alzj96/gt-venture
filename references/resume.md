# 接着上次：读档案、回访、复述

**什么时候读这份**：`archive.py find` 找到了这个项目的档案（没做完的、做完的、上次只做了筛查的），或者 `pattern.py show` 有输出。

## 第 0 步：先看有没有档案

用户可能是第一次来，也可能是回来接着上次的。**先查，别上来就问第一个问题。**

```bash
python3 <技能目录>/scripts/archive.py --workspace "$(pwd)" find
```

`find` 只告诉你有哪些档案、进行到第几问，**不含任何答案内容**。要复述就得把档案读出来：

```bash
python3 <技能目录>/scripts/archive.py --workspace "$(pwd)" show --project "<项目名>"
```

- **有档案且未完成** → 先 `show` 读出来，复述上次答过的要点，说"上次聊到第 N 问"，从断点继续。用户想重头再来也行，但要问一句——用 `AskUserQuestion`：「接着上次（推荐）」/「重头来」，后者写明「上次答过的会留在档案里，不删」。
- **有档案且已完成** → 摘要复述上次结论，**先回访上次的「下一步」**（见下），再问这次是想更新、还是诊断新项目。
- **上次是轻量筛查** → `find` 会明写"轻量筛查已做"。**别当成半途而废的诊断去接着问**，用 `AskUserQuestion` 问"上次只做了筛查，这次要不要走全面诊断"——两个选项，写明「答过的不会重问」。
- **没有档案** → 正常开场。

同时读一次跨项目模式：

```bash
python3 <技能目录>/scripts/pattern.py --workspace "$(pwd)" show
```

档案记的是"这个项目聊到哪"，模式记的是"这个人是什么样的人"。**一个人在项目 A 高估需求，在项目 B 大概率还会高估。**

有反复出现的倾向（≥2 次）时，在对应的那一问上多追一句；或者干脆在开头就说出来——「你上次也是在第 3 问这儿卡住，这次我会多问两句」。这比等他再撞一次有用。

**只说倾向，不提另一个项目的细节**（脚本输出里也会再提醒一次）。

**这份记录是关于"人"的，档案是关于"项目"的。** 同一个工作空间里有多个项目时，`show` 会问一句这些项目是不是同一个人的——**如果你在给不同客户做诊断，别让它们共用一个目录**，否则 A 客户的倾向会被套到 B 客户头上。

工作空间换了导致找不到旧档案时，明说"没找到历史档案，如果之前诊断过，把那个目录路径告诉我"，别默默当成新项目。

### 上次的「下一步」必须回访

档案里存着上次报告的「下一步」——那是一到三条这周能做完的具体动作。**不问一句就往下走，那几条就是摆设**，而且用户会发现这件事。

把它们读出来，逐条问做了没有：

> 「上次说的三件事：找王老师问她现在怎么批作业、找另外两个家长确认、去查一下小猿的免费功能。做了哪几件？」

三种回答，三种走法：

- **做了** → 这是这次对话里最值钱的材料，因为它是**新证据**，不是又一轮回忆。拿它去更新第 1、3 问的答案（`--append`），并记一条 `上次的作业做了` 的正向信号。
- **做了但结果和上次的判断不一样** → 更值钱。上次的结论要改，说清楚改哪一条、为什么。
- **没做** → **别追问原因，也别表现出失望。** 换成更小的那一个：「那我们把它砍小——这周只做一件事，给王老师发一条微信问她昨天批作业花了多久。」没做通常是因为上次给的动作太大，那是上一次诊断的问题，不是他的。

**一次都不回访的技能，等于每次都从零开始。** 档案让你记得聊到哪，回访才让上一次真的产生过作用。

**接上次时必须先复述再往下问。** 把第 1、2 问答过的要点用一两句说回去，加一句"有出入你打断我"。不复述直接说"接着第 3 问"会让用户不确定你到底记住了什么，而复述一遍的成本只有两句话。

重复问一遍用户已经答过的东西，是这类工具最容易让人不想再来第二次的原因。这一步的全部意义就在这。

### 接上次的项目不重做这一步

第 0 步的复述（把档案里答过的要点说回去）已经起到同样的作用，再重述一遍是浪费轮次。

**但要对一次**：他这次的说法和档案里记的不一样时，**当场指出来那个差异**，别默默用新的。

> 「上次你说是给家长用的，刚才你说的是老师。中间发生了什么？」

改口往往意味着他这段时间去问过人了——**那是这次对话里最值钱的一条信息，而它只在你对得够细的时候才会浮出来**。
