# 创业档案格式

脚本可用时不需要读这个文件。宿主不允许执行脚本、或没有 Python 时，按这里的结构手工读写，行为完全一样。

## 位置

```
<当前工作空间>/创业档案/<项目名>-诊断-<YYYYMMDD>.md
```

写在工作空间内，不写 `~/.xxx/`。原因：多数宿主的沙箱以工作空间为边界，写到外面会反复触发越权确认，把一次顺畅的对话变成一串弹窗。

项目名里的 `/ \ : * ? " < > |` 和空格替换成 `-`。

## 文件结构

```markdown
---
项目: 栖迟旅游定制
创建: 2026-09-15
更新: 2026-09-15
状态: 进行中
已答: 3
---

## 第1问 需求是真的吗

> 有两个老客户去年各付了 8000 让我帮他们排行程，不是朋友，是小红书私信来的。

## 第2问 现状替代品是什么

> 他们之前自己在马蜂窝和小红书上翻攻略，翻两三个晚上，然后还是拿不准住哪。

## 第3问 具体到绝望

> 未答

## 闸门检查

（第二步做完后写在这里，格式见 references/report-format.md 的「中国闸门」节）

## 报告

（第三步做完后追加完整报告）
```

## 字段说明

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `项目` | 用户给的项目名 | 同一工作空间下可有多个项目，按这个区分 |
| `创建` / `更新` | `YYYY-MM-DD` | `更新`用来判断档案新旧 |
| `模式` | `筛查` / `诊断` | 轻量筛查只查三项硬伤。**不标的话，一次完成的筛查会长得像一次半途而废的诊断** |
| `状态` | `进行中` / `已完成` | `已完成`表示报告已出 |
| `已答` | `0`–`6` | **已答问数的快照，不是断点**。断点看正文里第一个写着「未答」的问题（见下文） |

## 手工操作对照

| 脚本命令 | 手工等价动作 |
| --- | --- |
| `archive.py find` | 列出 `创业档案/` 下的 `.md`，读每份的 frontmatter，看 `项目`、`状态`、`已答` |
| `archive.py save --step N --answer "..."` | 在对应的 `## 第N问` 段落下写入用户原话，把 `已答` 改成 N，`更新` 改成今天 |
| `archive.py show --project X` | 直接打开那份 `.md` 读全文（第 0 步复述要用） |
| `archive.py gate --file X` | 把闸门结果写进 `## 闸门检查` 节下 |
| `archive.py report --file X` | 把报告内容写进 `## 报告` 节下，`状态` 改成 `已完成` |

**手工写入时必须自己做的两件事**（脚本会自动做，手工不会）：

1. **标题降两级。** 报告和闸门内容本身是 markdown，里面的 `#` 和 `##` 直接粘进去会和 `## 第N问` 变成同级，档案骨架就塌了。粘之前把 `#` 改成 `###`、`##` 改成 `####`，以此类推。
2. **断点看正文，不看 frontmatter。** `已答` 字段记的是写入顺序的最大值，跳着答会说谎（只答第 6 问也会显示 `已答: 6`）。真正的断点是**正文里第一个还写着「未答」的问题**。

## 两条要点

**存原话，不存概括。** 用户下次回来看到自己当时的原话，比看到你的总结有用得多——尤其是当他现在的说法已经和当时不一样的时候，那个差异本身就是最重要的信息。

**未答的问题写「未答」，别省略。** 空白和"跳过了"是两回事。报告里要能看出哪几问没答，因为那决定了结论有多不确定。

## 模式.md 的格式

`创业档案/模式.md` 记的是跨项目倾向，和某个具体项目无关，所以单独一个文件。

```markdown
# 跨项目模式

同一个人在不同项目上反复出现的倾向。只记倾向，不记项目细节。

最后更新: 2026-09-15

## 高估需求

- 2026-09-15　｜　第1问先说市场规模，追问才承认没人付过钱
- 2026-10-02　｜　又是朋友都说不错

## 说不出人

- 2026-10-02　｜　第3问只给了人群标签
```

七类固定词表：`高估需求` `说不出人` `楔子砍不动` `优势是通用能力` `跟风` `低估合规` `低估竞品`。

**手工记录时的三条规矩**（脚本会拦，手工要自觉）：

- **一条不超过 80 字**，只记倾向不记细节。这个文件每次诊断开头都会被读进上下文，A 项目的细节不该出现在 B 项目的对话里。
- **不写手机号、邮箱、人名、公司名。**
- **同一类型 ≥2 次才值得在开场提**。一次可能是偶然。

用户改掉了某个毛病，把那一整节删掉即可（脚本里是 `pattern.py retire --kind X`）——不删的话它会永远触发提醒，开场白慢慢变成一份罪状清单。

写了词表以外的类型也不会坏事：`show` 会原样显示并标注"手写类型"，`log` 也不会把它删掉。
