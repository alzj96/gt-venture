# 诊断报告格式

报告要能被用户转发给合伙人看，所以它得自己站得住——不依赖对话上下文。

## 结构

```markdown
# 诊断：<项目名>

日期：<YYYY-MM-DD>　｜　已答：<N>/6 问

## 概览
<**固定三行，格式不能改** —— 导出的 HTML 靠它画顶部的状态条，
写错格式就退化成普通列表，不会报错但会难看。>

- 结论：<做 / 改了再做 / 不做（该形态）>
- 闸门：人=<过|有问题|未查|不适用> / 事=<同上> / 地=<同上> / 钱=<同上>
- 已答：<N>/6

**四道闸逐格都要给一个字**，一格都不能省（见 [四道闸](gates.md)）：

- **过** —— 查过了，这一格没发现问题。**必须是查过，不是没看见**
- **有问题** —— 查到了要处理的东西
- **未查** —— 这一格我没覆盖，用户要自己查。**空着不写就等于说"没事"，那是这份报告最容易骗人的地方**
- **不适用** —— 这门生意不涉及这道闸（比如纯线下不涉及"地"）

下面那两份骨架（副业体检、轻量筛查）**只写「结论」那一行，不写「闸门」和「已答」**：
它们没走四道闸，凑一行闸门状态出来就是拿没查过的东西冒充查过了。
导出的 HTML 认这个格式——有结论就画结论，没有闸门就不画那四格。
**少一条状态条，好过多一条假的。**

## 一句话
<用一句话复述这个项目是什么。用用户自己的词，不要美化。
如果连一句话都说不清楚，那本身就是最重要的发现，直接写出来。>

## 这份判断踩在什么上
<第 2.5 步确认过的 3-5 条前提，每条标〔你说的〕〔我查的〕〔我推的〕，
并点出哪一条最要命——它错了整份结论会怎么变。
被用户推翻过的前提也写出来，连同推翻之后改了什么。

这一节是给转发对象看的：他得知道这份结论踩在什么上，才知道该不该信，
以及自己手上有没有能推翻某一条的信息。>

## 我听到的
<六问的答案，每问一段。引用用户原话，用「」标出。
没答的问题明确写「未答」，不要跳过——空白本身是信息。>

## 最硬的三个问题
<从答案里挑三个最站不住的地方。每个写：
- 我看到什么（引用原话）
- 为什么这是问题
- 什么样的证据能推翻我的判断

第三条是关键。给出可证伪的条件，用户才知道下一步该去验什么，
而不是只收到一个「你这不行」的判断。>

## 中国闸门
<按四道闸逐格写，一格都不能省——**没覆盖的那一格更要写**，那恰恰是用户要自己去办的事。

- **一、人**：谁来做这件事，身份上有没有限制。有原文的逐字引，带核对日期和来源链接。
- **二、事**：这门生意本身要不要经营许可。规则库整格空白，所以写三样：他的业务落在哪一类经营活动、去哪儿查（当地市场监管部门 / 12315 / 12345）、这是他几小时能查完的事。
- **三、地**：上哪个渠道，那个渠道要什么。只有微信小程序有规则原文；抖音、快手、支付宝、应用商店、网站、公众号一律写「未覆盖」，**不要拿微信的类目去套**。
- **四、钱**：要不要办执照、票怎么开。收预付款的另起一行写书面合同那条（2024-07-01 起）。

规则库没覆盖的，写「本次未覆盖，自己查：<链接>」，**不要留白**——留白会被读成"这一格没事"。
不确定的，写「待核实」，不要写「应该不用」。
**任何一格都不给"不需要办"这种否定结论**，理由见 SKILL.md「资质结论是重大主张」。>

## 如果只能做一件事
<最窄的楔子。具体到「先给谁、做什么一个功能、怎么算成功」。>

## 我否掉了什么
<一到两条看起来合理、但被否掉的路线。每条写：那条路是什么、否掉的理由是什么。

比如：「先做免费版攒用户再收费」——否掉的理由是你的核心功能正面站着一个
免费的行业巨头（小猿 AI，2026-09-15 核对），免费这条路上你没有位置。

**这一节不是给选项**，下面的结论还是那一个。它的作用是让用户能精确地反驳你：
他手上有你不知道的信息时（比如"那个巨头下个月要关掉这个功能"），
他知道该推翻哪一句。没有这一节，他只能整体接受或者整体不信。>

## 下一步
<一到三条具体动作，**每条用 `- [ ] ` 开头**——导出的 HTML 会把它画成可勾的清单，
用户能照着一条条划掉。必须是这周能做完的事，不是「去做市场调研」。

比如 `- [ ] 去找第 3 问里提到的那个人，问他上次是怎么解决的`。>

---
本报告基于你提供的信息和公开规则整理，**不构成法律、财务或投资意见**。
涉及资质、备案、税务的结论请以主管部门或专业人士的意见为准。
规则可能已变更，每条规则的核对日期见正文。
```

## 副业体检的报告（走四问的那条路）

**六问那个骨架对接单不适用**，硬套会出现「已答 3/6」这种对不上的东西。用这个：

```markdown
# 体检：<在做的事>

日期：<YYYY-MM-DD>　｜　副业体检

## 概览
- 结论：<一句话。**在职冲突那一节中了的，结论就写这个**，不写时薪——
  用户有权在往下读之前就知道这件事。>

## 你在做的是哪一种
<一句话说清楚：卖时间和手艺（接单），还是卖一个能脱离你运转的东西。
用户自己说的词和事情的性质不一致时，以性质为准，并把这个差异写出来。>

## 会不会出事（这一节永远排第一）
<在职冲突那三样的结论：兼职条款、竞业限制、职务发明归属。
每条写「查了没有 / 结论 / 他要回去核什么」。
没查的明写没查——这一节的空白比别处危险。>

## 这笔钱怎么算
<时薪算出来是多少（含沟通、改稿、催款的全时间）。
难看也如实写，但紧跟着给下面那条路径。>

## 时薪能怎么涨
<涨价 / 复用 / 交付出去，三条里挑最适合他的那一条，说清楚第一步做什么。
三条都挪不动的，明写「这是一份加班费更高的第二工作，不是副业」——
这话要写进去，因为很多人是带着"做副业改变命运"的预期来的。>

## 钱和风险
<书面凭据、尾款比例、税（劳务报酬 vs 经营所得）。>

## 下一步
<一到三条这周能做完的，**每条用 `- [ ] ` 开头**（导出的 HTML 会画成可勾的清单）。>

---
本报告基于你提供的信息和公开规则整理，**不构成法律、财务或投资意见**。
```

## 轻量筛查的报告（三项检查那条路）

**这份报告最容易写错，因为它必须同时给结论和给边界。**

```markdown
# 筛查：<项目名>

日期：<YYYY-MM-DD>　｜　轻量筛查（**不是诊断**）

## 概览
- 结论：<三样里命中了哪几条。**一条都没中也不许写「可以做」**，
  写「三样都没发现硬伤，但这只是筛查」。>

## 查了三样，结果是
1. **主体资格** —— <结论 + 具体依据（法规原文和日期），或者"没查出来">
2. **核心功能是不是已经免费** —— <竞品名字 + 它免费提供的具体功能 + 抓取日期，或者"没查出来">
3. **付费证据** —— <有/没有 + 用户原话>

<每一项都要给具体的东西。给不出的写「没查出来」，不要写「没问题」——
「主体资格看起来没问题」和「我问了，你们都不在体制内，这一项过」是两句话。>

## 没查的是这些
<固定四项，一个都不能省：你的用户具体是谁 / 最小能做到多小 /
你凭什么是做这件事的人 / 类目资质和行业规则。>

## 所以这份报告能说什么、不能说什么
**能说**：这三样里<没发现硬伤 / 命中了第 N 条>。
**不能说**：这事能不能做。**筛查通过不等于可以做**，它只说明没踩到这三个雷。

## 下一步
<命中硬伤的：那一条具体怎么办。
没命中的：要不要走全面诊断，以及已经答过的不会重问。>

---
本报告基于你提供的信息和公开规则整理，**不构成法律、财务或投资意见**。
```

**这份报告里绝不能出现的词**：可以做、看起来没问题、问题不大、应该可行。理由见 SKILL.md「轻量筛查的输出边界」。

## 写法要求

**给判断，不要给菜单。** 「你可以考虑 A、B 或 C」是把活推回给用户。说你认为哪个对，以及为什么。用户有你不知道的信息，他会自己推翻你——但他需要先有个东西可以推翻。

**「我否掉了什么」不违反这一条，它是这一条的配套。** 菜单是三个选项加一句"你自己看"；否掉的路线是一个结论加上"这两条我看过了，因为 X 和 Y 不走"。前者把决定权推回去，后者把**推翻你的抓手**递过去。区别在于有没有那个唯一的结论——有，就不是菜单。

写的时候检查一句：**这一节有没有可能被读成"其实 B 也行"？** 会的话就是写成菜单了，把否掉的理由写硬。

**引用原话。** 用户看到自己说过的话被摆在一起，往往比你的任何分析更有说服力。第 1 问说「大家都需要」、第 3 问说不出一个具体的人，这两句放在一起，结论不用你写。

**每个判断都配可证伪条件。** 不是「需求可能不真实」，而是「需求可能不真实。能推翻这个判断的是：你能找到 3 个在没有你的情况下，已经花钱或花时间自己解决这件事的人」。

**不要为了鼓励而稀释。** 用户来做诊断是想知道问题在哪。把「这个想法很有潜力」放在最前面，会让后面所有的话被当成客套。如果真的有强项，放在「最硬的三个问题」之后说，那时说的话才有分量。

**长度**：报告本身控制在一屏到两屏。分析越长，被读完的概率越低。

## 问答过程中的中间输出

问问题的过程中，如果需要给用户一个判断（比如用户问"你觉得这个方向对吗"），用这个更轻的结构：

```
<一句话结论，明说你的判断>
<为什么 —— 一到两句>
<什么能推翻它 —— 一句>
```

不要在六问没走完的时候写完整报告。中途的完整报告会让用户觉得已经结束了。
