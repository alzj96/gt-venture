# 知识库怎么用

**什么时候读这份**：第一次要查知识库之前——闸门检查时查这一行要什么许可，或者要说「这一行谁在做、收多少钱」。

## 一、先拆，再查

把项目拆成三块，**每块单独查**：

| 块 | 问的是 | 例：「帮宠物主找人上门喂猫的小程序，卖次卡」 |
| --- | --- | --- |
| **做什么事** | 这件事本身属于哪一行 | 上门喂养宠物 |
| **在哪个渠道** | 在哪儿上线、在哪儿卖 | 微信小程序 |
| **怎么收钱** | 钱怎么进来 | 次卡（先收钱后兑付）、个人微信收款 |

不拆直接查「宠物小程序」，查到的要么是宠物、要么是小程序，**两头的闸都会漏一半**。

## 二、每块调 `kb_lookup.py`，只读命中的那一两节

```bash
python3 <技能目录>/scripts/kb_lookup.py 上门喂猫 宠物
```

它返回命中的文件和章节标题（带行号），**只读那几节，不要把整份卡、更不要把索引整份读进来**——读进来的都会一直留在对话里。没命中它会明说「知识库没有」。

查完合起来：

- **四道闸取并集**：几块各自要过的闸合在一起。同一道闸几块要求不一样时，**许可按最严的那条算**
- **横向规则卡每个项目都过一遍触发条件**：网络交易、直播营销、广告用语、个人信息、生成式 AI、食品网络销售、预付式消费、电商经营者登记、商业特许经营（招加盟商或者去加盟）。**交叉品类的风险大部分出在这里，不在品类本身**——上面那个例子，最先要补的是预付式消费（次卡），不是宠物那一行的许可

## 三、条目标着档位，照档位说

| 档位 | 引用时怎么说 |
| --- | --- |
| **规则** | 逐字原文 + 拉取日期 + 来源链接。标 `待证` 的：**不逐字引、不报金额、不给具体数字** |
| **公开数据** | 说来源和日期 |
| **行业报道** | 说来源和日期，**只作参考，不拿它下结论** |
| **经验估计** | **每次都说「这是估计」**，并说依据 |

- **过期的照样能用，但要说出来**：规则超过 90 天、公开数据和行业报道超过 180 天，说「这条最后核对于 X，可能已经变了」
- 「拉取日期在保质期内」只说明我们最近抄过，**不说明它还有效**
- **哪一档都不给否定结论**——不说「不需要办证」「你这个规模不用办」

## 四、拆完查不到，或者是分类表里没有的新业态：联网

照 [联网核实](../web-check.md) 的规矩：**先脱敏**；抓官网正文，不停在搜索摘要；标〔我查的〕和查询日期。

**搜到的只算线索，不是规则**：不当成法规原文逐字引，不给否定结论。说法是「我查到 X 在做、官网写收 Y（〔我查的〕，日期），这不是一手的监管口径」。

## 五、报告里记一行缺口

查不到的那一块，在报告「中国闸门」一节和闸门存档里各写一行：

> 知识库缺口：<哪一块>——查了 <关键词>，库里没有；<联网查到了什么 / 没查到>

运行时写不了技能目录，缺口就留在报告和档案里。**用户实际撞到的缺口，就是下一批该做的卡。**

**知识库只在开发阶段更新**：抓一手源、人工核过再发版。运行时联网是补这一次诊断的缺口，结果不进库。
